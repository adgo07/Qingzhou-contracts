## 3. 实现方法

- 用户任务、结果与可读依据优先。普通页面使用业务字段名，技术标识按既有诊断边界管理。
- Domain / Application 不依赖 Widget、平台弹窗或控件状态；家族一致性不要求业务表单、页数与流程完全相同。
- 按 A-01～A-07 组织入口和业务壳。使用可辨识的当前位置、选中、禁用与键盘焦点状态；状态不只靠颜色。最近工作、帮助和关于按已有能力保留。
- 按 A-08～A-11 组织标准和记录。列表可分页或按需加载，核对全部记录可达；复杂详情在既定结构内分区。业务状态与软件支持状态分别解释。
- 按 A-12～A-15 落实报告、导入、库和新建边界。四区域是信息分组，避免强制四次确认；简单任务可用单页分区，复杂任务保留必要专业步骤。计算与保存延续业务批准规则。
- 按 A-16～A-18 核对信息层级与中文可读性。推荐一致的间距、按钮语义与表格反馈，考虑长文本、高 DPI、键盘操作及缩放；具体数值按第 4 节的当前实施基准，保持可演进。
- Error / Warning / Info 使用产品交付治理第 21.3 节。错误就近提示，不因统一设计新增警告阻断、必填配置或技术中心。
- 显示修约不反馈正式判定。隐藏来源或审计区域不删除底层证据、快照、版本与追溯数据。

### 界面文案与信息密度

本节是 Owner 于 2026-11-10 确认的文案精简规则与必要例外的唯一正文，落实产品家族规格 A-16～A-18；经中央 PR 合并后适用，仍属于 ACTIVE / EVOLVING 指南，不是 Frozen Contract。不改变既有功能范围、计算或保存语义，也不要求为本节启动三仓全面重构。

默认按以下六条设计和检查实际页面。判断依据是信息是否重复、是否帮助用户决策、删除后是否影响使用，不机械考核字数或把所有页面压成一句话。

| 编号 | 默认规则 | 适用边界 |
|---|---|---|
| 文案-01 | 标题已能表达页面或分区用途时，不添加复述标题的副标题。 | 只有补充适用范围、当前对象或关键限制的信息才保留。 |
| 文案-02 | 不默认给每个模块、卡片、字段添加说明文字。 | 优先通过准确名称、布局、单位和控件状态表达含义；必要信息按下述例外直接显示。 |
| 文案-03 | 通用免责声明和更新时间集中在页面唯一页脚，只出现一次，不在模块、卡片或弹窗中重复。 | 无此信息时不为凑页脚新增；更新时间须指明更新对象。标准实施日期、记录生成时间等业务数据仍放在对应位置，不并入通用更新时间。 |
| 文案-04 | 按钮采用清楚的动作文字，优先“动词＋对象”，必要时说明直接结果。 | 删除“点击按钮即可……”等操作复述；“保存项目”“生成记录”“导出报告”须对应真实动作，不能借改名改变流程。 |
| 文案-05 | 空状态默认只保留一句说明和一个最相关的操作按钮。 | 区分首次无数据、筛选无结果和读取失败；没有可执行动作时不强加按钮，不借空状态开放新功能。 |
| 文案-06 | 补充解释放入就近的 ⓘ 提示气泡，默认收起。 | 支持点击和键盘打开、关闭，入口有可理解的名称，不仅依赖鼠标悬停；没有补充内容时不添加图标。 |

**必要例外：影响正确填写、判断结果或确认操作的信息，必须在相关字段、结果或动作附近直接可见。** 包括必填标记、单位、输入错误、结果过期、功能未开放、计算后是否生成正式记录，以及删除、覆盖或恢复的影响。这些信息不能只放在提示气泡或页脚，也不能以“精简”为由删除。操作后果若已由按钮准确表达，不再重复附注；按钮不足以表达时保留最短必要说明。长篇背景解释可以收起，关键限制和当前状态仍须直接可见。

例子：

- “标准库”下方的“在这里查看标准库中的标准”删除；确有不同适用范围时保留具体范围。
- 按钮写“导出报告（Word）”，不另写“点击导出按钮即可导出报告”。
- 首次空状态：“暂无核算记录”＋“新建核算”；筛选无结果：“没有匹配的记录”＋“清除筛选”；读取失败：“记录读取失败”＋“重试”。示例动作仅在已有相应能力时使用。
- 按钮若仅写“计算排放量”且实际会生成记录，可就近说明“计算完成后自动生成记录”；不能将其当作重复操作说明隐藏。

验收动作见[验收清单的文案与信息密度检查](UI_ACCEPTANCE_CHECKLIST_V0.1.md#5-界面文案与信息密度检查)。保留例外时简述其业务原因，不把补充说明气泡变成承载全部业务信息的唯一入口。

## 4. 家族实施数值与方法

本节是规格第 4 节的共同数值与方法基准，保持 ACTIVE / EVOLVING，不冻结像素，也不要求旧页面全面重构。必要业务差异须说明原因。

### 4.1 尺寸、窗口与布局

尺寸和字号按 Qt DIP（逻辑像素）表达。控件高度按最终外框验收，包含 padding / border；字体 pointSize 不可直接当 pixelSize 使用。

| 对象 | 当前基准 |
|---|---|
| 首次窗口客户区 | 目标 1280×800，非最大化；系统边框后整窗不超过当前屏幕工作区 |
| 低屏幕 | 可缩至约 960×600；屏幕更小时继续约束，不用硬最小尺寸把动作推出屏幕 |
| 业务侧栏 / 导航 / 图标 | 242 / 46 / 18 |
| 业务正文 | 居中，最大 1440；单层外边距 `clamp(22, 0.034 * 业务内容可用宽, 48)`；宽度取侧栏之外、施加本边距前的可用宽，避免重复嵌套边距 |
| 普通单行输入 / 按钮 | 最终外框 40；仅明确密集行内区域统一 36，同组不忽大忽小；多行按内容 |
| 圆角 | 面板 10、任务卡 14、输入 / 按钮 6、导航 9 |
| 表格行 | 默认 48、最低 44；长文本动态增高，不截中文；表内小动作按行高适配，无需一律 40 |
| 页签 | 最终高 36，字号 13 / 字重 600，选中底线 2 |
| 滚动条 | 宽 10，核对实际可拖动与点击操作 |
| Logo | 首页、侧栏统一目标宽 180，高约 44.65（按原图比例）；容器足够高，不裁透明原图 |

窗口行为见[规格 §4.1](UI_PRODUCT_FAMILY_SPEC_V0.1.md#41-窗口与页面基准)。按各屏幕实际工作区约束整窗，不用虚拟桌面外接矩形代替可用区；恢复状态须保留正常窗口位置与尺寸。

### 4.2 字体与颜色

| 对象 | 当前基准 |
|---|---|
| 字体回退 | Microsoft YaHei UI → Microsoft YaHei → 系统中文字体 |
| 标题 | 业务页 24 / 600；首页 30 / 800；分区 16 / 600 |
| 正文与辅助 | 正文 14；说明 / 表头 / 导航 13；表头及导航字重 600 |
| 品牌装饰 | `#197CC2` |
| 主按钮白字底色 | 正常 `#116FAE`，hover `#0D6097` |
| 正文 / 标题 / 次文字 | `#213A4F` / `#18364F` / `#526A7D`；旧 `#698198` 仅装饰或禁用 |
| 表头文字 / 导航未选中文字 | `#526A7D`；导航选中时采用下列选中颜色 |
| 页面 / 卡片 / 弱底 / 边框 | `#F5F8FC` / `#FFFFFF` / `#F7FAFD` / `#DAE7F1` |
| 状态 | 成功 `#168268`、提醒 `#956420`、危险 `#B9484A`，同时用文字表达 |
| 导航选中 | 底 `#D6EBF9`、字 `#116FAE`、条 `#298CCB`；hover 底 `#EDF6FD` |
| 输入键盘焦点 | 可见 2 DIP 边框 / 焦点环，预留空间，状态切换不跳尺寸 |

`#197CC2` 配白字对比约 4.46，低于普通文字 4.5，因此普通白字主按钮采用上表深蓝。其他状态按规格 §4.2 保持一致、清晰，显式覆盖角色与禁用状态组合，不另增未经批准的色板。

### 4.3 输入、表格与页面实现

使用本产品的统一控件角色或样式辅助方法，不建立跨仓 runtime package。只读内容保持可读、可复制；Decimal 输入保持无损文本路径，不用格式化回写截断精度。

表格按字体、列宽与换行内容调整行高；宽表在自身区域横滚，底部计数与翻页 / 加载控件可达。输入、焦点和增删折叠行为见规格 §4.2，不在指南重复页面功能名单。

### 4.4 Logo 与高 DPI

使用[正式品牌及图标资产与来源说明](assets/README.md)。动作图标以其中的 symbol 映射为准，可拆为 Qt 独立 SVG、换色和 DPR 绘制，但保留 path 几何与线宽比例，不依赖历史原型。

Logo 从原图按目标 DIP × 当前窗口 DPR 重采样，并设置对应 pixmap DPR（或等效绘制）；保持比例、透明与高质量缩放。尺寸或屏幕 DPI 变化后从原图重绘，不放大已缩小位图。

坐标和图像像素的换算见 [Qt High DPI 文档](https://doc.qt.io/qt-6/highdpi.html)。不永久覆盖系统 DPI 设置；离屏属性检查不能代替真实多屏验收。

### 4.5 实施与验证成本

按实际改动选择代表页面和必要验证，见[验收清单 §4](UI_ACCEPTANCE_CHECKLIST_V0.1.md#4-共同实施基准检查)。只改文案不要求补齐四类页面截图或高 DPI 测试。复用 PR 中的简短证据，不要求全矩阵截图或无关业务回归；源码与打包运行结果分别记录。

其他平台 UI、全局搜索与多标签工作区允许按业务需求探索，不能覆盖 A 类决定或自动扩大批准范围。公共语义不足按[变更流程](../governance/CHANGE_PROCESS.md)提出 RFC / ADR。
