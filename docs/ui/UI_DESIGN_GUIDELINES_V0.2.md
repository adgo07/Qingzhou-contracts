## 3. 实现方法

- 用户任务、结果与可读依据优先。普通页面使用业务字段名，技术标识按既有诊断边界管理。
- Domain / Application 不依赖 Widget、平台弹窗或控件状态；家族一致性不要求业务表单、页数与流程完全相同。
- 按 A-01～A-07 组织入口和业务壳。使用可辨识的当前位置、选中、禁用与键盘焦点状态；状态不只靠颜色。最近工作、帮助和关于按已有能力保留。
- 按 A-08～A-11 组织标准和记录。列表可分页或按需加载，核对全部记录可达；复杂详情在既定结构内分区。业务状态与软件支持状态分别解释。
- 按 A-12～A-15 落实报告、导入、库和新建边界。四区域是信息分组，避免强制四次确认；简单任务可用单页分区，复杂任务保留必要专业步骤。计算与保存延续业务批准规则。
- 按 A-16～A-18 核对信息层级与中文可读性。推荐一致的间距、按钮语义与表格反馈，考虑长文本、高 DPI、键盘操作及缩放；具体数值按第 4 节的当前实施基准，保持可演进。
- Error / Warning / Info 使用产品交付治理第 21.3 节。错误就近提示，不因统一设计新增警告阻断、必填配置或技术中心。
- 显示修约不反馈正式判定。隐藏来源或审计区域不删除底层证据、快照、版本与追溯数据。

## 4. 家族实施数值与方法

本节落实规格第 4 节 Owner 本轮授权的行为，是当前家族实施基准；不再将已明确数值一概列为 B 类可任意选择。保持 ACTIVE / EVOLVING，可随后续明确决定调整，不冻结像素，不追溯要求旧页面全部重构。业务特殊布局须说明必要差异，不改变业务批准边界。候选身份与实施授权见规格第 1 节。

### 4.1 尺寸、窗口与布局

下列尺寸均为 Qt DIP（逻辑像素）。控件高度指**最终外框**，不是 QSS 内容高度；使用 height/min-height 加 padding/border 时应实测 widget.geometry，避免外框膨胀。字体数值同样按逻辑像素表达，QFont 的 pointSize 不可直接当 pixelSize 使用。

| 对象 | 当前基准 |
|---|---|
| 首次窗口客户区 | 目标 1280×800，非最大化；系统边框后整窗不超过当前屏幕工作区 |
| 低屏幕 | 可缩至约 960×600；屏幕更小时继续约束，不用硬最小尺寸把动作推出屏幕 |
| 业务侧栏 / 导航 / 图标 | 242 / 46 / 18 |
| 业务正文 | 居中，最大 1440；单层外边距 `clamp(22, 0.034 * 业务内容可用宽, 48)`；宽度取侧栏之外、施加本边距前的可用宽，避免重复嵌套边距 |
| 普通单行输入 / 按钮 | 最终外框 40；仅明确密集行内区域统一 36，同组不忽大忽小；多行按内容 |
| 圆角 | 面板 10、任务卡 14、输入 / 按钮 6、导航 9 |
| 表格行 | 默认 48、最低 44；长文本动态增高，不截中文；表内小动作按行高适配，无需一律 40 |
| 页签 | 最终高 36，字号 13 / 字重 600，选中底线 2 |
| 滚动条 | 宽 10，核对实际可拖动与点击操作 |
| Logo | 首页、侧栏统一目标宽 180，高约 44.65（按原图比例）；容器足够高，不裁透明原图 |

首次窗口基于当前 `QScreen.availableGeometry()` 约束并居中，计入 frame 与 client 的差额；窗口显示取得真实边框后再次校正。后续恢复本产品 geometry 与 window state，保留正常窗口尺寸以便退出最大化；恢复失败或掉屏时按仍存在的屏幕工作区收回，不能只判断虚拟桌面 bounding rectangle。Qt 多屏可能存在坐标间隙，应枚举实际屏幕。窗口恢复实现不得复用或改写业务 Workspace 恢复策略。

### 4.2 字体与颜色

| 对象 | 当前基准 |
|---|---|
| 字体回退 | Microsoft YaHei UI → Microsoft YaHei → 系统中文字体 |
| 标题 | 业务页 24 / 600；首页 30 / 800；分区 16 / 600 |
| 正文与辅助 | 正文 14；说明 / 表头 / 导航 13；表头及导航字重 600 |
| 品牌装饰 | `#197CC2` |
| 主按钮白字底色 | 正常 `#116FAE`，hover `#0D6097` |
| 正文 / 标题 / 次文字 | `#213A4F` / `#18364F` / `#526A7D`；旧 `#698198` 仅装饰或禁用 |
| 页面 / 卡片 / 弱底 / 边框 | `#F5F8FC` / `#FFFFFF` / `#F7FAFD` / `#DAE7F1` |
| 状态 | 成功 `#168268`、提醒 `#956420`、危险 `#B9484A`，同时用文字表达 |
| 导航选中 | 底 `#D6EBF9`、字 `#116FAE`、条 `#298CCB`；hover 底 `#EDF6FD` |
| 输入键盘焦点 | 可见 2 DIP 边框 / 焦点环，预留空间，状态切换不跳尺寸 |

`#197CC2` 配白字对比约 4.46，低于普通文字 4.5；因此用于装饰，普通白字主按钮采用上表深蓝。其余按钮的 pressed / focus / disabled / busy 用一致角色规则实现，保持文字清晰；不额外规定未经批准的新色板。QSS 应显式覆盖角色与 `:disabled` 的组合，核对选择器优先级，避免 primary 重新启用视觉；busy 由实际任务生命周期驱动，完成、失败、取消均重新计算可用条件。

### 4.3 输入、表格与页面实现

用统一控件角色或本产品样式辅助方法落实规格第 4.2 节，不为视觉建立跨仓 runtime package。对只读字段保留可读、可复制行为，与禁止交互的 disabled 外观分开。沿用可无损承接 Decimal 文本的输入路径，验证编辑前后文本与业务值，不通过格式化回写截断精度。下拉框滚轮处理应尊重焦点和明确操作，不让表单滚动意外改变值。

表格按字体度量、列宽及换行内容动态计算行高，必要时随列宽变化重算；宽表可在自身区域横滚，不能靠固定行高裁掉中文。保持列表底部计数和现有翻页 / 加载控件可达。动态对象增删与折叠保留合理滚动锚点，内联错误可定位到字段，不抢走正在输入的焦点。

页面组织行为只在规格维护，本指南不复制逐产品功能名单。业务词、原文入口、记录快照、计算与保存规则按规格和业务仓批准范围落实。

### 4.4 Logo 与高 DPI

使用[正式品牌及图标资产与来源说明](assets/README.md)。动作图标以其中的 symbol 映射为准，可拆为 Qt 独立 SVG、换色和 DPR 绘制，但保留 path 几何与线宽比例，不依赖历史原型。

Logo 每次从原图按目标 DIP × 当前窗口 `devicePixelRatio` 生成 pixmap，并设置相同 DPR，或使用等效高 DPI 绘制；例如宽 180 DIP、DPR=2 时取约 360 个像素宽，逻辑宽仍为 180。保持比例、透明和高质量缩放。resize 及跨 DPI 屏幕切换后从原图重绘，不能把上次缩小的 pixmap 再放大。

Qt 的窗口 / 控件坐标与图像像素不是同一单位，屏幕列表也不能假定连续，参见 [Qt 官方 High DPI 文档](https://doc.qt.io/qt-6/highdpi.html)。不通过永久覆盖系统 DPI 设置掩盖实现问题。DPR 属性检查和离屏测试可提供实现证据，不等于真实多屏或人工界面验收。

### 4.5 实施与验证成本

只对涉及页面运行必要测试。同窗口与 DPI 保留首页、标准库或记录、新建、详情四个代表视图，加一次高 DPI 抽查；不要求全矩阵截图、重复证据或全量业务回归。优先复用已有短报告 / PR 说明，清理只限本次改动直接相关且已证实无效的样式，不删除历史资产或业务证据。源码启动与打包启动分别记录，不能以源码成功宣称 EXE 通过。具体核对动作见清单。

其他平台 UI、全局搜索与多标签工作区允许按业务需求探索，不能覆盖 A 类决定或自动扩大批准范围。公共语义不足按[变更流程](../governance/CHANGE_PROCESS.md)提出 RFC / ADR。
