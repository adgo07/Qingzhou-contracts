## 1. 当前适用状态与边界

三个软件仍在持续开发，本指南建立当前统一设计基线，不冻结最终 UI，不是新的 UI Contract。经中央 PR 审查合并后，v0.2 成为当前适用指南，[v0.1](UI_DESIGN_GUIDELINES_V0.1.md) 原文保留为历史版本，不与 v0.2 并行规定当前页面。合并前本版本为本轮待验收提案，不宣称已生效。

本指南遵循 [产品交付治理规则](../governance/PRODUCT_DELIVERY_POLICY_V1.md)、[Architecture V2.1](../architecture/ARCHITECTURE_V2.1_FROZEN.md) 与业务仓锁定的 Frozen Contract。ACTIVE 指南按中央当前已合并适用版本读取；Frozen 文件仍按 `platform-lock.json` locked SHA 读取，详见 [阅读路由](../GUIDE_INDEX.md)。读取新指南不构成 Contract adoption，不修改锁定文件。

QZ-UI-02 只执行 Phase 0 只读盘点和 Phase 1 中央设计文档更新，不进入 Phase 2，不制作正式 UI、不修改业务仓代码。后续三个业务仓继续独立开发、发布与离线运行，其他正常业务任务无需等待本轮 UI 方案。

不建立公共 PySide6 package、跨仓运行时依赖或 UI Contract；不修改 Frozen Architecture、Numeric Contract、标准解释、Calculator、Canonical、数据库 Schema 或任何 `platform-lock.json`。展示重组不改变业务真值或历史正式结果。

## 2. A / B / C 分类

| 类别 | 含义 | 使用方式 |
|---|---|---|
| A：Owner 当前已确认 | 当前实施依据 | 后续相关 UI 任务遵循；Owner 可修改，不是永久冻结 |
| B：推荐设计模式 | 帮助落实 A 的方式与未确认细节 | 按实际业务调整，不作固定布局门槛 |
| C：待开放 / 允许探索 | 尚未开放或未确认的能力 | 如实标识，不伪装已支持，不永久禁止未来实现 |

A 类集中定义在 [产品家族规格](UI_PRODUCT_FAMILY_SPEC_V0.1.md) 第 2～5 节；[验收清单](UI_ACCEPTANCE_CHECKLIST_V0.1.md) 按编号引用。不得将示例、推荐或 AI 推测升级为 Owner 决定。

## 3. 延续的产品原则

- Windows-first、中文优先、用户任务优先，结果和可读计算依据优先；Windows-first 不等于 Windows-only architecture。
- PySide6 / Qt Widgets 是当前桌面默认方向，但不因本轮治理迁移成熟 UI；如实记录遗留或实验入口。Domain / Application 不依赖 Widget、平台弹窗或控件状态。
- 普通页面使用业务字段名，不用 JSON key、内部 Rule ID、Calculator 名或 trace 组织主操作；内部技术标识按既有诊断边界管理。
- 少填少选少确认、渐进展示；Error / Warning / Info 沿用产品交付治理规则第 21.3 节，不另造等级或增加警告阻断。
- 显示修约不得反馈正式判定；保留底层追溯、证据、快照及版本数据，不因隐藏来源或审计区域删除数据。
- 家族一致性不要求业务表单、页数、流程和像素完全相同，不创造统一业务引擎。

**R1 最新 Owner 决定（A 类）：** 标准库仅提供关键词（编号、名称、适用对象）和标准状态筛选，编号与名称都能进入详情；标准详情单页连续展示基本信息、适用范围、标准要求，不使用页签，不设置独立“软件支持范围”。记录详情仍严格保留两个页签。用户可见的“Excel导入”统一更名为“表格导入”；标准要求、数据检查、计算和结果须精炼，不堆砌重复卡片与长篇说明。所有对外文字、交互按钮、提示与状态尽量中文，标准编号、品牌、计量单位和文件格式等必要英文可保留。

## 4. B 类推荐模式

### 4.1 基础视觉与可用性

专业简洁、信息层级清楚。推荐一致的标题层级、间距习惯、按钮语义、状态表达和表格反馈。同类动作采用相同含义与风格的 SVG 图标，并有可理解的中文名称。图标品牌、资产库及具体 token 待后续选择，不要求共享安装依赖。

推荐可辨识的选中、禁用和键盘焦点状态；状态不只靠颜色区分，考虑中文长文本、高 DPI、键盘操作与窗口缩放。具体色号、字号、卡片尺寸、导航宽度和像素布局不冻结。

### 4.2 首页与业务壳

按 A-01～A-06 实现首页无侧栏与业务壳的切换。首页可用简洁按钮或入口卡片体现标准库优先、新建业务次之，设置独立。最近工作、帮助、关于可按真实能力保留，不要求新增 Dashboard。

业务页推荐保留当前位置与选中态，未完成输入按已有业务规则处理，不增加统一草稿机制。首页进入设置时侧栏如何处理尚为 OPEN。

### 4.3 标准库与记录

按 A-08～A-11 使用五列标准列表、标准详情单页三分区、搜索与完整记录列表及独立两页签记录详情。五列名称已确认，具体列宽、排序和状态词汇仍可调整。标准状态与软件支持状态分别解释，不用“已收录”冒充正式支持。

完整记录列表可分页或按需加载，但不能固定截断最近若干条且其余记录不可访问。详情可独立页面或对话框承载，展示保存时输入、结果与依据，不按最新标准包重算。两个页签内可以分区，不另加审计详情入口、页签或重新开展业务动作。

### 4.4 表格导入、新建与设置

四区域是任务信息分组，不强制四步向导、四次确认或相同正式导入能力；见规格第 6 节。未开放入口保持可见且禁用，不要求先实现空页面。

新建业务只统一五类功能。简单标准推荐单页分区，复杂核算可保留现有表单、页签与专业步骤；不把五类功能变成强制五页签，不增加 EquipEffi 草稿或额外保存。

设置推荐仅放用户可理解选项，技术诊断按已有方式承载，不因本轮新增必填配置、保存手续或技术中心。

## 6. C 类与演进

ECQuota 表格导入 / 折标系数库当前未开放，GHGTOOL Excel 保持只读预览；未来正式导入等能力允许通过业务仓独立任务评估。EquipEffi 当前不强制增加参数库，未来真实需求出现时可另行设计。

全局搜索、其他平台 UI、多标签工作区等可探索，不要求三仓同步，不覆盖 A 类决定，不自动扩成本轮 Phase 2。能力开放必须有真实实现和适用范围证据，不能仅因显示入口就宣称正式支持。

未确认事项见规格第 7 节 OPEN 表。Owner 后续修改同步更新指南、规格、阅读路由与清单；B 类细节无需冻结才能试验。若涉及公共语义，按 [变更流程](../governance/CHANGE_PROCESS.md) 处理。
