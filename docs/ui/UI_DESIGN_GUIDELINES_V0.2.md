# 青舟桌面 UI 设计指南 v0.2

状态：**ACTIVE / EVOLVING**
更新：2026-10-26（增补 B 类家族视觉默认值）
适用：ECQuota、EquipEffi、GHGTOOL Windows Desktop。产品设计指南，不是 Frozen Contract。

## 1. 当前适用状态与边界

读取中央当前已合并适用版本，见[读取导航](../GUIDE_INDEX.md)。遵循[产品交付治理](../governance/PRODUCT_DELIVERY_POLICY_V1.md)与业务仓 locked Frozen Contract；不修改锁定文件，不构成 Contract adoption，不授权成熟 UI 迁移或公共 UI package。展示重组不改变 Calculator、标准解释、Canonical、数据库或历史结果。

## 2. 单一决定正文

[产品家族规格](UI_PRODUCT_FAMILY_SPEC_V0.1.md)第 2～5 节是当前公共 UI 决定及待迁移约束的唯一正文；[验收清单](UI_ACCEPTANCE_CHECKLIST_V0.1.md)只提供核对动作。

A 类为 Owner 当前实施依据，可按批准流程修改；B 类是推荐；C 类为未确认或待开放事项。推荐、示例与 Agent 推测不得升级成批准决定。既有 Owner 产品批准继续有效；职责下沉不是重新授权，业务仓按既有批准流程维护和变更。

## 3. 实现方法

- 用户任务、结果与可读依据优先。普通页面使用业务字段名，技术标识按既有诊断边界管理。
- Domain / Application 不依赖 Widget、平台弹窗或控件状态；家族一致性不要求业务表单、页数与流程完全相同。
- 按 A-01～A-07 组织入口和业务壳。使用可辨识的当前位置、选中、禁用与键盘焦点状态；状态不只靠颜色。最近工作、帮助和关于按已有能力保留。
- 按 A-08～A-11 组织标准和记录。列表可分页或按需加载，核对全部记录可达；复杂详情在既定结构内分区。业务状态与软件支持状态分别解释。
- 按 A-12～A-15 落实报告、导入、库和新建边界。四区域是信息分组，避免强制四次确认；简单任务可用单页分区，复杂任务保留必要专业步骤。计算与保存延续业务批准规则。
- 按 A-16～A-18 核对信息层级与中文可读性。推荐一致的间距、按钮语义与表格反馈，考虑长文本、高 DPI、键盘操作及缩放；具体 token 和像素不冻结。
- Error / Warning / Info 使用产品交付治理第 21.3 节。错误就近提示，不因统一设计新增警告阻断、必填配置或技术中心。
- 显示修约不反馈正式判定。隐藏来源或审计区域不删除底层证据、快照、版本与追溯数据。

## 4. 推荐与探索

仅针对改动页面检查可用性，不要求三仓同步全面 UI Audit。图标资产、四区域标题、排序、宽度和承载方式等未确认细节按规格 OPEN 项处理，不作为固定布局门槛。

### 三软件统一视觉默认基准（B 类）

为避免同类页面分别形成不同风格，ECQuota、EquipEffi、GHGTOOL 的新 UI 或局部改版**优先从同一组视觉默认值起步**。这是可按业务密度、窗口尺寸和平台字体调整的设计参考，不是 Frozen Contract、像素锁定或新增功能授权；无需为符合本节重构已稳定的页面。

| 视觉对象 | 推荐默认值（Qt 逻辑像素 / QSS 参考值） |
|---|---|
| 品牌蓝、正文、次文字 | `#197CC2`、`#213A4F`、`#698198` |
| 页面底、白色内容区、弱底、细边框 | `#F5F8FC`、`#FFFFFF`、`#F7FAFD`、`#DAE7F1` |
| 状态色 | 成功 `#168268`、提醒 `#956420`、危险 `#B9484A`；同时显示文字，不仅靠颜色 |
| 业务侧栏 | 浅蓝纵向渐变参考 `#E6F2FC → #EDF6FD → #E6F2FB`；宽度约 242，导航项高约 46，顶部真实 LOGO、底部独立设置 |
| 侧栏选中项 | 浅蓝底 `#D6EBF9`，文字 `#116FAE`，左侧强调线 `#298CCB`，保留焦点状态 |
| 字体与层次 | 系统可用的 Microsoft YaHei UI / Microsoft YaHei；业务页标题约 24/600，分区标题 16/600，正文 14，说明 13 |
| 页面布局 | 业务内容居中、参考最大宽度约 1440；外边距弹性约 22～48，不向每层嵌套布局叠加相同边距 |
| 卡片与控件 | 首页任务卡圆角约 14；业务面板约 10；输入/按钮约 6；常用输入框与按钮最终外框高度以约 40 为起点，完整显示中文与焦点边框 |
| 表格与图标 | 表格最小行高约 40 并随内容增高，宽表在自身区域横滚；同义动作使用一致的 SVG 图标，常用导航图标约 18 |

推荐按**控件角色**统一，而非要求所有页面使用相同面积的大卡片：无侧栏首页可使用深蓝重点入口与白色普通任务卡；业务页采用浅底白面板、清晰标题、主蓝按钮／描边次按钮／轻量行内动作，危险动作独立。搜索列表与业务值确认应区别处理，打字不能丢焦点、覆盖用户值；普通折叠、启停和增删不得无故跳顶。复杂多组录入以“业务分区 → 独立对象组 → 组内明细”体现边界，简单标准不强制二级目录或项目草稿。

具体视觉实现可参考 [GHGTOOL PR60 已合并 UI（固定源码提交）](https://github.com/adgo07/GHGTOOL/tree/6fc5909646b855494abee55cff6fd95f8d18b4be) 和 [GHGTOOL PR61 的产品设计参考稿（固定提交；尚待该业务 PR 合并）](https://github.com/adgo07/GHGTOOL/blob/5308eee1bebae13a7cfddb8e53b021be3978885f/docs/ui/GHGTOOL_UI_DESIGN_REFERENCE.md)。它们是**产品实例**，不是新的中央权威；不复制碳排放八类排放源、Excel/Project/Record 处理链、专业字段或未开放能力，不引入跨仓 UI 运行时依赖。

只对实际改动的代表页面使用同窗口尺寸截图抽查视觉一致性，并保留必要差异原因；不规定像素相似度、不要求完整 DPI 截图矩阵或三软件联合验收。

其他平台 UI、全局搜索与多标签工作区允许按业务需求探索，不能覆盖 A 类决定或自动扩大批准范围。公共语义不足按[变更流程](../governance/CHANGE_PROCESS.md)提出 RFC / ADR。

## 5. 版本关系

[v0.1](UI_DESIGN_GUIDELINES_V0.1.md)是保留原文的历史指南；[Phase 2](phase2/README.md)是固定版本历史原型。两者退出当前实施和生产验收路由，旧断言不能验收新产品；历史证据按[历史索引](../history/README.md)读取。

后续修改决定时更新规格的唯一正文，并同步必要导航与验收动作，避免在本指南重写字段、页签或逐产品能力名单。
