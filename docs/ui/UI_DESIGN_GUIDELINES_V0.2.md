状态：**ACTIVE / EVOLVING**

适用：ECQuota、EquipEffi、GHGTOOL Windows Desktop。产品设计指南，不是 Frozen Contract。

## 1. 当前适用状态与边界

读取中央当前已合并适用版本，见[读取导航](../GUIDE_INDEX.md)。遵循[产品交付治理](../governance/PRODUCT_DELIVERY_POLICY_V1.md)与业务仓 locked Frozen Contract；不修改锁定文件，不构成 Contract adoption，不授权成熟 UI 迁移或公共 UI package。展示重组不改变 Calculator、标准解释、Canonical、数据库或历史结果。

## 2. 单一决定正文

[产品家族规格](UI_PRODUCT_FAMILY_SPEC_V0.1.md)第 2～5 节是当前公共 UI 决定及待迁移约束的唯一正文；[验收清单](UI_ACCEPTANCE_CHECKLIST_V0.1.md)只提供核对动作。

A 类为 Owner 当前实施依据，可按批准流程修改；B 类是推荐；C 类为未确认或待开放事项。推荐、示例与 Agent 推测不得升级成批准决定。既有 Owner 产品批准继续有效；职责下沉不是重新授权，业务仓按既有批准流程维护和变更。

## 3. 实现方法

- 用户任务、结果与可读依据优先。普通页面使用业务字段名，技术标识按既有诊断边界管理。
- Domain / Application 不依赖 Widget、平台弹窗或控件状态；家族一致性不要求业务表单、页数与流程完全相同。
- 按 A-01～A-07 组织入口和业务壳。使用可辨识的当前位置、选中、禁用与键盘焦点状态；状态不只靠颜色。最近工作、帮助和关于按已有能力保留。
- 按 A-08～A-11 组织标准和记录。列表可分页或按需加载，核对全部记录可达；复杂详情在既定结构内分区。业务状态与软件支持状态分别解释。
- 按 A-12～A-15 落实报告、导入、库和新建边界。四区域是信息分组，避免强制四次确认；简单任务可用单页分区，复杂任务保留必要专业步骤。计算与保存延续业务批准规则。
- 按 A-16～A-18 核对信息层级与中文可读性。推荐一致的间距、按钮语义与表格反馈，考虑长文本、高 DPI、键盘操作及缩放；具体 token 和像素不冻结。
- Error / Warning / Info 使用产品交付治理第 21.3 节。错误就近提示，不因统一设计新增警告阻断、必填配置或技术中心。
- 显示修约不反馈正式判定。隐藏来源或审计区域不删除底层证据、快照、版本与追溯数据。

## 4. 推荐与探索

仅针对改动页面检查可用性，不要求三仓同步全面 UI Audit。图标资产、四区域标题、排序、宽度和承载方式等未确认细节按规格 OPEN 项处理，不作为固定布局门槛。

其他平台 UI、全局搜索与多标签工作区允许按业务需求探索，不能覆盖 A 类决定或自动扩大批准范围。公共语义不足按[变更流程](../governance/CHANGE_PROCESS.md)提出 RFC / ADR。

## 5. 版本关系

[v0.1](UI_DESIGN_GUIDELINES_V0.1.md)是保留原文的历史指南；[Phase 2](phase2/README.md)是固定版本历史原型。两者退出当前实施和生产验收路由，旧断言不能验收新产品；历史证据按[历史索引](../history/README.md)读取。

后续修改决定时更新规格的唯一正文，并同步必要导航与验收动作，避免在本指南重写字段、页签或逐产品能力名单。
