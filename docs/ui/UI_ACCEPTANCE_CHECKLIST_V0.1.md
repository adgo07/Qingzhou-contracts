## 4. 共同实施基准检查

按规格第 4 节行为、指南第 4 节参数，仅核对改动涉及的项目；无关项记 N/A，不要求每次重复全部页面或状态组合。

- [ ] 窗口行为改动：用独立临时配置检查首次居中与整窗工作区约束；检查重启恢复、掉屏后可达及小屏滚动，不改变业务恢复规则。
- [ ] 布局或共用样式改动：从首页、标准库或记录、新建、详情中选受影响的代表视图，在一致窗口 / DPI 下核对尺寸、字体和按钮角色；跨页面共用样式才覆盖这些页面类别。涉及缩放或资产绘制时增加高 DPI 抽查。
- [ ] 控件或异步动作改动：核对相关正常、悬停、按下、焦点、禁用、忙碌状态；检查前置条件、防重复提交、失败 / 取消后的可用状态及安全退出。
- [ ] 输入或表单交互改动：用高精度十进制和空白核对编辑 / 失焦后文本与值；检查焦点、下拉滚轮、清除筛选、刷新及增删折叠不误改输入或跳位。
- [ ] 表格改动：用长中文、多行与列宽变化检查完整可读性，底部计数及既有分页 / 加载控件可达，旧记录可访问。
- [ ] 状态展示改动：核对生命周期、支持状态、标准角色的映射证据；替代与废止不混同，日期不足不判现行，缺证据记 OPEN。未开放入口禁用且状态直接可见，文案按第 5 节检查。
- [ ] 品牌绘制改动：核对正式原图、透明等比、逻辑宽度与 DPR；尺寸 / 跨 DPI 变化后从原图重绘。离屏检查如实标注，不冒充人工多屏验收。

## 5. 界面文案与信息密度检查

规则与必要例外只维护在[指南：界面文案与信息密度](UI_DESIGN_GUIDELINES_V0.2.md#界面文案与信息密度)。对当前任务涉及的实际页面和状态进行以下观察，记录 PASS / FAIL / OPEN / N/A；未实际查看记 OPEN，不以源码或文档存在代替 UI 通过。保留例外时简述业务原因，不用字数或按钮数量机械判定。

- [ ] 文案-01：逐项比较标题和副标题，确认保留内容提供新增信息。
- [ ] 文案-02：检查模块、卡片和字段说明，确认无默认铺满的重复解释。
- [ ] 文案-03：检查整页及相关弹窗，核对通用免责声明/更新时间的唯一位置，并确认业务日期仍在对应对象处。
- [ ] 文案-04：对照按钮真实动作检查文字，确认无“点击按钮即可……”复述，且项目保存、生成记录与导出文件没有混淆。
- [ ] 文案-05：分别查看首次无数据、筛选无结果、读取失败，核对一句说明及相关可执行动作；无动作场景不强加按钮。
- [ ] 文案-06：观察解释默认收起，实际用鼠标点击与键盘打开、关闭 ⓘ 提示，确认入口名称可理解，内容可读且不只依赖悬停。
- [ ] 必要例外：查看输入无效、结果过期、未开放功能及有后果的操作，确认关键标记、单位、错误、限制和保存/删除/覆盖/恢复影响直接可见；不因精简隐藏必要信息或改变业务行为。

- [ ] 查看、导出记录使用保存时快照，历史结果不因当前数据升级漂移；显示修约不反馈正式判定，隐藏技术区域不删除证据和追溯。
