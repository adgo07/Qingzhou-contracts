## 1. 适用与分类

配合 [UI 指南 v0.2](UI_DESIGN_GUIDELINES_V0.2.md) 使用，经中央 PR 合并后适用。三个软件仍在持续开发，A 类为 Owner 当前实施依据且允许后续修改；B 类为推荐；C 类为待开放 / 探索。Phase 0 代码盘点与 SHA 留在本轮 PR，不额外建立大型审计文档。

本轮只执行 Phase 0～1，不实现 UI，不改三仓代码、业务真值、Schema 或 `platform-lock.json`，不建立公共 UI package 或跨仓运行时依赖。

## 4. 首页与业务壳

```text
启动 → 首页（无侧栏）
首页已开放业务入口 → 业务页（显示侧栏）
业务页间切换 → 保留侧栏
左侧“首页” → 首页（无侧栏）
```

A 类确定顶部 LOGO、底部独立设置。首页入口采用“标准库 → 新建业务 → 表格导入 → 业务记录 → 适用的参数库”，设置独立。B 类推荐中间任务顺序：首页 → 标准库 → 对应新建业务 → 表格导入 → 对应记录 → 产品专属库；不额外锁定全部侧栏顺序。首页标准库先于新建业务的优先级仍为 A 类。

首页设置的具体呈现及其侧栏行为为 OPEN；帮助、关于和最近工作按已有能力保留，不成为新增强制入口。

## 5. 真实能力边界（A 类约束 / C 类待开放）

| 产品 | 当前约束 | 后续相关 UI 实施 |
|---|---|---|
| ECQuota | 表格导入、折标系数库当前未开放 | 显示但禁用，不伪造导入或可维护库，允许未来独立开放 |
| ECQuota | 不设置报告导出 | 不暴露报告导出，保留已有底层适配、兼容和数据能力 |
| EquipEffi | 不增加草稿与额外保存流程 | 合法分析结果按现有规则形成记录，不增加“保存草稿 / 保存正式记录”步骤 |
| EquipEffi | Excel 已有批量处理实现 | 如实表现模板、检查、批量评价、结果工作簿与批次总结；实现不替代独立验收状态 |
| EquipEffi | 不强制参数 / 因子库 | 不为凑齐导航增加空库 |
| GHGTOOL | Excel 仍为只读预览 | 不自动创建正式记录，不称为正式导入或核算完成 |
| GHGTOOL | 工作区与正式记录分别管理 | 保留现有工作区恢复、正式记录只读查看边界，不合并对象或增加统一保存机制 |
| GHGTOOL | 已有参数与因子库 | 名称统一不扩大现有编辑能力、数据来源或标准支持范围 |

未开放不等于永久禁止实现；后续通过各业务仓独立任务开放并记录能力证据，不因统一视觉自动升级支持状态。

## 6. B 类推荐设计

### 6.1 标准库

五列固定：标准编号、标准名称、标准状态、实施日期、软件支持；列宽与排序不冻结。关键词匹配编号、名称与适用对象；仅提供标准状态筛选，编号或名称均可打开详情；标准生命周期状态与软件支持状态分别解释，不发明公共状态枚举或混成含糊“可用”。

标准详情单页三个连续分区：

- 基本信息：编号、名称、发布日期、有效日期、可理解状态，不显示发布单位。
- 适用范围：标准适用对象、必要条件，不额外设置软件支持范围。
- 标准要求：核心指标、必要限值、单位、条件和关键依据，按已有证据精炼展示，不重写标准解释。

查看标准原文作为操作保留，不借此设置来源或关系区域。文件不可用时清楚解释，不假定捆绑全量 PDF，不要求核心计算在线。

### 6.2 业务记录

搜索、完整列表、独立详情分工明确。详情可独立页面或对话框，不把同屏长文本当作最终独立详情。“基本信息与结果”展示业务对象和保存时核心结论；“输入数据与计算依据”展示保存时业务输入与可读依据。复杂明细在两个页签内分区，不新增审计详情，不重算历史正式记录。

### 6.3 表格导入四区域

四区域数量为 A 类，以下标题和动作安排为 B 类，待后续确认：

| 建议区域 | ECQuota | EquipEffi | GHGTOOL |
|---|---|---|---|
| 1 模板与说明 | 未开放说明 | 当前模板、泵型与支持范围 | 当前预览支持范围与说明 |
| 2 文件选择 | 禁用 | 选择工作簿 | 选择用于预览的工作簿 |
| 3 数据预览与检查 | 禁用 | 导入检查与反馈，按真实能力展示 | 只读预览与校验反馈 |
| 4 处理结果 | 禁用 | 批量评价、结果工作簿、批次总结 | 只读预览反馈，不创建正式记录 |

ECQuota 保留禁用入口即可，不要求先做空四区域页面。四区域不强制四步向导或重复确认。GHGTOOL 仍可保留真实模板下载，不把下载模板误认为具备正式导入能力。

### 6.4 库、新建与设置

参数 / 因子类库推荐搜索、列表和可读详情，编辑与版本能力只按产品真实范围提供，不发明公共 Quantity / Unit 语义。

新建五类功能按复杂度组织，可以是一页分区或既有表单 / 页签。数据检查、计算和结果宜紧凑精炼，不添加冗余卡片及长篇重复说明；错误尽量就近提示。计算与正式保存行为延续各软件业务规则。

设置推荐只展示用户可理解选项，诊断按已有方式管理，不新增强制配置或技术中心。
