## 1. 适用与分类

配合 [UI 指南 v0.2](UI_DESIGN_GUIDELINES_V0.2.md) 使用，经中央 PR 合并后适用。三个软件仍在持续开发，A 类为 Owner 当前实施依据且允许后续修改；B 类为推荐；C 类为待开放 / 探索。任务盘点与核查 SHA 留在对应 PR，不额外建立大型审计文档。

本规格维护公共 UI 决定。具体能力由业务仓按既有批准流程维护和变更；既有 Owner 批准决定继续有效，本次职责调整不是重新授权，不允许 Agent 自行开放功能。本文不授权 UI 重构、Contract 升级或新增运行时依赖。

## 3. Owner 当前决定（A 类）

| 编号 | 当前实施依据 | 边界 |

| A-02 | 首页标准库入口位于新建业务入口之前 | 具体按钮或卡片形式为 B 类 |
| A-03 | 首页设置独立于主要业务入口 | 不混入主要业务入口组 |
| A-04 | 进入业务页面显示并保留左侧导航；点击左侧首页才返回无侧栏首页 | 业务页切换继续显示侧栏；禁用入口不能进入未开放流程 |
| A-05 | 左侧导航淡蓝风格、顶部 LOGO、底部独立设置 | 不锁定具体色号、宽度和 LOGO 尺寸 |
| A-06 | 三软件统一 SVG 图标与基础视觉语言 | 不要求公共安装或运行时包 |
| A-07 | 未开放功能显示但禁用 | 说明当前状态，不禁止未来实现 |
| A-08 | 标准库关键词搜索编号、名称、适用对象，仅标准状态筛选；五列固定；点击标准编号或名称均进入详情；标准详情单页连续三个分区 | 五列为“标准编号、标准名称、标准状态、实施日期、软件支持”；分区为“基本信息、适用范围、标准要求”，不使用详情页签，也不设软件支持筛选框 |
| A-09 | 标准详情不显示发布单位、标准关系与来源区域；适用范围不显示“软件支持范围”；保留查看标准原文 | 软件支持仍在列表第五列，不删除底层来源与证据 |
| A-10 | 记录采用搜索、完整列表、独立详情；详情严格两个页签 | “基本信息与结果”“输入数据与计算依据”；所有记录可达 |
| A-11 | 记录页不提供基于记录重新开展业务，不提供审计详情 | 不加审计入口或第三页签；保留底层追溯 |
| A-12 | 报告 / 导出能力由各业务仓按既有批准产品范围、真实实现与验收状态维护 | 中央不登记逐标准名单；报告使用所选记录保存时的数据、结果及适用依据，不因当前规则更新改变历史结论；职责调整不撤销既有批准，也不自动扩大能力 |
| A-13 | 表格导入统一四区域结构，尊重各软件当前真实能力 | 不借改名扩展支持文件格式或正式计算、保存能力 |

| A-15 | 新建只统一基本信息、业务数据、数据检查、计算、结果五类功能 | 不强制统一表单、页签、步骤或业务逻辑 |
| A-16 | 视觉专业简洁 | 不冻结具体色号、字号、卡片尺寸或像素布局 |

| A-18 | 用户可见的标题、按钮、提示、状态尽量中文 | 标准编号、品牌、单位、文件格式及技术标识保留必要准确原文 |

## 4. 首页与业务壳的落实

按 A-01～A-07 处理入口与壳切换。B 类推荐中间任务顺序：首页 → 标准库 → 对应新建业务 → 表格导入 → 对应记录 → 产品专属库；不额外锁定全部侧栏顺序。

首页设置的具体呈现及其侧栏行为为 OPEN；帮助、关于和最近工作按已有能力保留，不成为新增强制入口。

## 5. 真实能力与决定承接

## 6. B 类推荐设计

### 6.1 标准库

按 A-08、A-09 组织列表和详情；列宽、排序与具体状态词汇可按业务调整。标准生命周期与软件支持状态分别解释，不发明公共枚举。查看原文失败时解释文件可用性，不要求核心计算在线。

### 6.2 业务记录

按 A-10、A-11 分配搜索、完整列表与独立详情。列表可分页或按需加载，避免固定截断；复杂明细可在既定结构内分区，展示保存时快照。

### 6.3 表格导入四区域

按 A-13 组织四个信息区域，推荐“模板与说明、文件选择、数据预览与检查、处理结果”。标题与动作由业务仓结合批准范围及真实能力安排，不强制四步向导或重复确认。禁用入口无需先实现空页面；模板下载不等于正式导入能力。

### 6.4 库、新建与设置

参数 / 因子类库推荐搜索、列表和可读详情，编辑与版本能力只按产品真实范围提供，不发明公共 Quantity / Unit 语义。

新建五类功能按复杂度组织，可以是一页分区或既有表单 / 页签。数据检查、计算和结果宜紧凑精炼，不添加冗余卡片及长篇重复说明；错误尽量就近提示。计算与正式保存行为延续各软件业务规则。

设置推荐只展示用户可理解选项，诊断按已有方式管理，不新增强制配置或技术中心。
